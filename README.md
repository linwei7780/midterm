# 生理監控與多重感官警報系統 (NUCLEO-G474RE 期中專題)

使用者心跳異常或長時間無訊號時，傳統環境未能及時發出多重感官警報，導致照護盲點與危機延誤。

## 1. 情境故事：
* **人物/場景**：獨居長者或居家療養患者在家中或病房休息。
* **遇到麻煩**：當心率異常飆高（過勞/情緒起伏）或發生心跳停搏（超過 4 秒無脈衝訊號）時，若無即時的視聽覺警報系統，家屬或照護人員無法第一時間察覺並進行危機處理。

## 2. 替身對照：
* 生理脈搏感測器 → 外接按鈕（接於 `PC10`，手動按壓模擬心跳脈衝）
* 心跳指示/狀態燈 → 綠燈 (`PA7`) 與紅燈 (`PA5`)
* 呼吸調理引導燈 → 藍燈呼吸燈 (`PA8`，透過 `TIM1_CH1` PWM 控制)
* 緊急蜂鳴警報器 → 有源蜂鳴器 (`PA6`，透過 `TIM3_CH1` PWM 控制)

## 3. 功能與驗收條件：
* **正常狀態 (`STATE_NORMAL`)**：平緩藍燈 2 秒呼吸燈循環；紅燈、綠燈與蜂鳴器關閉。
* **壓力狀態 (`STATE_STRESS`)**：模擬心率介於 $100 \sim 150\text{ BPM}$ 時，綠燈常亮，藍燈維持呼吸。
* **異常警報狀態 (`STATE_ALARM`)**：心率超過 $150\text{ BPM}$ 或超過 4 秒無按壓訊號時，綠燈熄滅，藍燈急速爆閃、紅燈點亮、蜂鳴器同步高頻鳴叫（$100\text{ms}$ 週期）。

## 4. 用到的技術：
* [x] GPIO 輸入與輸出控制（按鈕內部上拉、LED 點亮與控制）
* [x] TIM 計時器與 PWM 輸出（`TIM1_CH1` 藍燈呼吸燈、`TIM3_CH1` 蜂鳴器）
* [x] 非阻塞式延遲 (`HAL_GetTick()`) 與有限狀態機 (FSM) 架構
* [x] 二次方 Gamma 校正（放慢暗部變化，消除 LED 視覺跳階感）

## 5. 腳位表：
* `PA8` = `TIM1_CH1` (藍燈 PWM 呼吸燈輸出)
* `PA6` = `TIM3_CH1` (蜂鳴器 PWM 警報輸出)
* `PA5` = 紅燈 (異常警報指示輸出)
* `PA7` = 綠燈 (心率偏高/壓力狀態指示輸出)
* `PC10` = 外接按鈕輸入（內部上拉 `GPIO_PULLUP`，另一端接 `GND`）

## 6. 建置與執行：
* **開發環境**：STM32CubeIDE (基於 GCC ARM 工具鏈)
* **燒錄步驟**：透過 ST-LINK USB 連接開發板至電腦，點擊 STM32CubeIDE 的 **Run/Debug** 按鈕進行編譯與燒錄。
* **操作方式**：透過麵包板上的外接按鈕（接在 `PC10`）以不同頻率點擊來模擬心率。

## 7. 程式結構：
* `main.c`：包含系統狀態機（`SystemState_t`）、按鈕心率計算（`Process_Button_HeartRate`）、狀態機更新（`Update_State_Machine`）、正常呼吸燈控制（`Handle_Normal_Breathing`）與異常警報控制（`Handle_Alarm_State`）。
* **分工**：主迴圈 `while(1)` 持續執行非阻塞的按鈕偵測、狀態機更新與對應感官輸出；全程式採用 `HAL_GetTick()` 實現非阻塞計時，未動用額外硬體中斷 ISR。

## 9. AI 使用說明：
* **AI 協助部分**：請 AI 協助建構非阻塞式狀態機邏輯、二次方 Gamma 呼吸燈數學轉換公式，以及除錯 STM32CubeIDE 專案中的編譯器相容性與 `TIM` 巨集問題。
* **查核方式**：實際動手燒錄觀察 LED 亮度漸變平順度與蜂鳴器鳴叫頻率是否符合 $100\text{ms}$ 爆閃與 2 秒呼吸週期，驗證邏輯正確性。

## 10. 已知限制：
* **已知限制**：目前以手動點擊按鈕（`PC10`）模擬心跳訊號，而非真實光學 PPG 或心電圖（ECG）感測器。
* **換真貨改法**：若要換成真實生理感測器，只需將 `Process_Button_HeartRate()` 替換為 ADC 或 UART 讀取真實心跳脈衝資料，並將心率數值帶入 `bpm` 變數即可無縫銜接狀態機。
